# 연구와 운영을 업그레이드하는 방법

연구 문서 갱신, Buzz 구성 변경, 예측 방법 검증을 별도로 관리한다. 현재 자동화는 문서 조사·토론·검토다. 모델 학습과 성능 승격까지 자동으로 구현된 것은 아니다.

## 현재 구현과 개선 후보

| 범위 | 현재 가능한 일 | 다음 개선 후보와 수용 기준 |
| --- | --- | --- |
| 연구 문서 | 공식 자료·원논문 조사, 반론, 후보 검토, 버전 보존 | 새로운 주장마다 원문·시각·범위·반증 연결 |
| 상태 관리 | run manifest, 입력 해시, 중복 방지 계약 | closed run의 waiting_for 비우기, canonical_changed와 result 일치 검사 |
| 라우팅 | 원래 시작 이벤트를 root로 고정하는 계약 | 모든 요청·회신·최종 보고가 동일 root인지 검사 |
| 시간 제한 | 후속 메시지에서 90분 초과 확인 | 필요가 입증되면 별도 watchdog 설계·중복 종료 테스트 |
| 복원 | 프롬프트·설정·증거 보존 | 새 환경 bootstrap·재시작 후 실제 응답 검증 |
| 예측 성능 | 검증 설계와 요구사항 문서 | PIT 자료·권리·사전등록·전향 평가를 확보한 실제 실험 |

후보 목록은 구현 완료나 실행 승인이 아니다. 증거는 [인계 상태](../ARCHIVE-STATUS.md), [갱신 이력](../research/samsung-forecast-2026-11/buzz/changes.md), [지연 분석](../incidents/2026-11-10-buzz-migration-latency.md)에서 확인한다.

## 연구 내용 개선

1. 현행 결론의 약점 한 개를 고른다. 예: 공시의 실제 가용 시각이 확인되지 않음.
2. 확인할 질문과 성공 조건을 정의한다. 예: 공식 문서로 발행·수집·정정 시각을 구분할 수 있음.
3. `[S80-CYCLE]` 요청에 질문을 적고 현행 운영 계약을 유지한다.
4. 데이터·퀀트·산업의 독립 근거와 반론을 받는다.
5. 변경 후보와 현행 문서의 diff를 검토한다. 새 근거가 없으면 NO_CHANGE로 끝낸다.
6. 문서 검사·정확한 후보 SHA 외부검토 이후에만 정본을 갱신한다.
7. 채택·기각 이유, 미해결, 전후 해시를 보존한다.

예시:

```text
@S80-총괄 [S80-CYCLE] 이번에는 예측 마감 전 공시 가용 시각을 검증해줘. 공식 문서로 확인 가능한 범위와 미확인 범위를 구분하고, 기존 PIT 계약을 보존해줘. 권한·유료 데이터·앱 코드는 변경하지 마.
```

## 프롬프트·계약·예약 개선

진행 중 입력을 수정하면 해시 차단이 발생한다. 2026-11-10 실제 TEAM 변경 실패를 근거로, 다음 순서를 사용한다.

1. 채널에서 중지를 요청하고 필요하면 예약도 비활성화한다.
2. 진행 run과 모든 작업자의 종료를 확인한다. 시간 경과만으로 종료를 추정하지 않는다.
3. 현재 운영 파일과 UI 설정을 안전한 범위에서 보존하고 Git 기준 commit을 확인한다.
4. 새 branch와 `deployment/<revision>/`에서 필요한 프롬프트·계약만 수정한다.
5. 한 번에 한 가지 문제를 고친다. 원래 모델·권한·비용 범위를 임의 확대하지 않는다.
6. 정적 검사 후 새 run으로 bootstrap·역할 왕복·후보 검토를 확인한다.
7. PR에 목적, 변경점, 실제 검증, 미검증, 되돌리기를 기록한다.
8. 승인된 범위에서 배포하고 실제 Buzz UI 저장·회신을 확인한다. Git merge만으로 운영 적용 완료라고 쓰지 않는다.
9. 명시적으로 STOP을 해제하고 예약을 활성화한다. 첫 실제 연구 결과를 확인한다.

구성 변경 전 기록할 값: 채널·Workflow·신원 ID, 실행 경로, 모델 UI 값, 프롬프트 SHA, 계약 SHA, 현재 run, STOP·예약 상태. 비밀값은 기록하지 않는다.

실패하면 새 실행을 중지하고 종료를 확인한다. 이전 승인 구성으로 복구한 뒤 새로운 run과 입력 해시로 검사한다. 이전에 닫은 run을 다시 열거나 과거 결과를 덮어쓰지 않는다.

## 예측 방법과 성능 진화

80% 목표는 실제 실험을 거쳐야 한다. 문서 합의, 리뷰 PASS, 기사 수 증가를 성능으로 쓰지 않는다.

- 자료 이용권, 시점 기준(PIT), 정정·거래 캘린더·누락·보합·보류 처리를 확정한다.
- 예측 대상과 전체 평가 분모를 고정한다. 선택한 날의 적중률과 전체 거래일 적중률을 섞지 않는다.
- 특징값·학습 창·재학습 방식·비교 기준선·검정을 사전등록한다.
- 시간 분리와 미래 정보 차단을 유지한다. 최신 LLM의 과거 재생을 전향 평가로 표시하지 않는다.
- 기존 방법과 후보를 같은 대상·기간·마감 조건에서 비교한다.
- 표본·불확실성·누락·실패를 함께 보고한다. 표본 부족이면 승격을 보류한다.
- 공개된 예측·평가는 보존하고 새 방법은 새 버전으로 적용한다.

세부 통계 계약은 [연구 정본](../research/samsung-direction-80-research-2026-11.md)과 [퀀트 검증](../research/samsung-forecast-2026-11/02-quant-validation.md)을 따른다. 새 임계값이나 목표 달성 수치를 이 가이드에서 만들지 않는다.

## 다음 보존본 저장

현재 저장소의 `archive/source-inventory.json`은 최초 보존본이다. 이후 갱신은 `snapshots/<UTC시각>/`에 추가하고 새 inventory·SHA256SUMS를 만든다. 완료 run만 복사하고 복사 전후 원본 SHA가 같은지 확인한다. 새 README 포인터로 최신 스냅샷을 연결한다. 최초 증거의 SHA 목록을 새 파일에 맞춰 덮어쓰지 않는다.

정기 연구가 이 GitHub 저장소를 자동 push하는 기능은 없다. 채널 실행 완료 후 검토된 보존 작업을 별도로 수행한다.
