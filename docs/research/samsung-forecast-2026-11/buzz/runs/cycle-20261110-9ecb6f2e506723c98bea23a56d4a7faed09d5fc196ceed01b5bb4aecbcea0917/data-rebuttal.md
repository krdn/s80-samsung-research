## R3의 R1 질문에 직접 답변

**질문:** IR→DART→전문 재발행 체인에서 최초 사용 가능한 버전·시각과 미확인을 어떻게 구분하는가? 접수일만 있는 사건과 권리 미해결 파생 라벨은 어떻게 처리하는가?

**답변:** 사건ID와 문서 버전ID를 분리하고 각 버전의 실제 입증 범위를 기록한다. 체인이 반드시 그 순서로 공개됐다고 가정하지 않는다. 다음은 수집·입력 적격성 제안이며 현재 확보된 증거가 있다는 주장이 아니다.

| 구분 | 필요한 증거 | 증거가 없을 때 |
|---|---|---|
| 사건·문서 식별 | 회사·사건 종류·대상 기간·공식 URL, DART는 접수번호·원/정정 연결, 문서별 버전ID·해시 | 서로 다른 문서를 같은 사건으로 연결했다는 추론과 확인을 분리. 재인용을 독립 사건으로 증가시키지 않음 |
| 과거 공개·가용 | 해당 버전과 연결된 공식 공개시각·시간대 또는 검증 가능한 과거 공개 기록, 정정·재게시 관계 | 현재 페이지 날짜·HTTP 메타데이터만으로 과거 버전 시각을 확정하지 않음. DART YYYYMMDD도07:40 적격 증거가 아님 |
| 실제 운영 수신 | 당시 수집 로그·수신시각·버전과 내용 해시·동결 입력 해시, 수집기·추출기 버전 | 오늘 처음 읽은 시각을 과거 최초 수신으로 소급하지 않음. 해시만 있고 내용·시각 연결이 없으면 충분하지 않음 |
| 권리 | 공급자·자료·목적별 열람/원문 보관/백업/추출·모델 입력/파생 라벨 보관/타인 열람 범위 | 공개 열람 허용을 다른 용도 허용으로 확대하지 않음. 권리 불명은 허용 판정도 일괄 위법 판정도 아님. 연구 채택은 보류 |

**최초 사용 가능의 뜻:** 확인한 적격 버전들 중 각 버전의 공개·가용 시각과 실제 수신 시각 중 늦은 시각을 보수적으로 사용한다. 그중 가장 이른 적격 시각은 ‘증거로 확인한 버전 집합 안에서 최초’일 뿐 전 세계 최초 공개시각이 아니다. 출처·버전·권리 적격성도 충족해야 한다. 시각의 날짜만 알면 시각은 미확인으로 남긴다.

먼저 확보한 IR이 결의 사실만 입증하고 DART에 새 세부조건이 추가됐다면, 나중 조건을 IR의 이른 시각에 붙이지 않는다. 뒤늦은 전문에서만 발견한 발언도 앞선 발표일로 소급하지 않는다. 같은 사건의 원/정정은 별도 버전으로 연결하고 원래 입력·예측을 보존한다.

**역사 제외와 전향 관찰:** 접수일만 있거나 당시 문서·가용시각을 복원하지 못한 특징은 해당 역사 시험에서 제외한다. 시점이 복원된 역사 연구도 당시 실제 운영 수신 증거가 없으면 실운영 성적으로 쓰지 않는다. 최신 LLM의 과거 재생·2026 산업 자료에 노출된 M3는 기존 개발 자료·lockbox 계약을 따른다. 전향 관찰은 권리 해결과 사전 고정한 가용시각 판정 규칙, 실제07:40 이전 수신·동결이 갖춰진 뒤 후보가 된다. 오늘 첫 확인은 향후 검증 기록의 시작이 될 수 있지만 시장의 신규 사건 발생은 아니다.

**파생 라벨 권리:** 허용된 링크·최소 메타데이터·연구 요약과 모델용 사건 라벨 데이터셋을 구분한다. 원문 저장권이 없어도 라벨은 자유롭다고 추정하지 않는다. 추출·라벨 보관·학습의 허용 범위를 확인하지 못하면 모델 데이터셋으로 보관·학습하는 채택을 보류한다. 권리 미해결 라벨을 ‘사건 없음’0으로 채우지 않는다. 기록 가능한 허용 범위의 권리 상태·제외 사유만 남긴다. 이미 동결된 예측·평가를 유리하게 재작성하는 근거로 삼지 않는다.

## R2 P1·반례·SPA에 대한 반론과 답변

**사실:** R2는 P1을 실행 전 사전등록 제안으로 썼고 시장의 의존도 추정·실제 오류율로 주장하지 않았다. `p=0.8, rho=0.95, n=250`일 때 모든 hit가1일 확률은 `0.8×0.99^249=0.065501831`, 이에 따른 포함률 상한은 `0.934498169`다. 이 두 수치를 Python 표준 계산으로 재확인했다. 전체 DP 분포·Wilson 표·실제 bootstrap·전체 승격 규칙은 이번 R1이 재실행하지 않았다.

**반론1 — 반례가 검증하는 대상:** 이 반례에서는 예정일250개의 hit가 모두 존재한다. 실제 수집 지연·권리 제외·미발표·평가불가가 있는 운영 원장은 다르다. 반례의 정당성을 수용하되 실제 hit 생성과 결측을 혼합해 예측 실패 빈도나 전체 오합격률로 전이하지 않는다. 여러 기관의 같은 사건 재인용도 새로운 독립 표본이 아니다.

**반론2 — P1의 자료가용성:** 적중일만 남긴 배열을 만들면 정시 제공 실패가 사라진다. P1이 제안한 동일 날짜 벡터를 실제로 구성할 때 예정일·원자료 버전·권리 상태·입력 결측·제공/보류·라벨 가용·사후 평가 정정을 분리해야 한다. 시각/권리 미확인은 관측한 ‘사건 없음’0과 다르다. 사건 군집·국면 변화·운영 누락 모수는 가상 스트레스 조건 또는 개발 추정값인지 구분하고, 증거 없는 값은 시장 추정치로 붙이지 않는다.

**반론3 — P1의 권리:** 무료 생성 모의자료로 절차를 점검할 수 있어도 실제 공급자의 보관·라벨·ML 권리나 과거 PIT가 생기지 않는다. 결측으로 M2 fallback을 허용한다면 그 규칙도 M3의 고정 절차와 탐색 이력에 포함해야 한다. 같은 날짜·라벨로 공통 비교하되 M3 가능일만 남긴 성적과 전체 예정일 A_all을 모두 보존한다. 권리 미해결 자료를 시뮬레이션 통과로 채택하지 않는다.

**SPA 적용 범위에 대한 답변:** Hansen의 recursive 제외는 원문에서 확인했다. expanding을 단순 rolling으로 바꾸면 현재 자료의 정상성·손실차이 양의 분산·정정/PIT가 해결된다는 추론은 기각한다. 이 원논문의 틀 밖이라는 사실을 모든 expanding 예측 평가가 불가능하다는 주장으로도 확대하지 않는다. 적절한 별도 이론·검증 없이 SPA라는 이름을 붙여 합격시키지 않는다. 즉시 통계법·재학습 방식 변경은 제안하지 않는다.

**판단·수정 제안:** P1을 기존 ‘개발자료에서 적절성·검정력 점검’을 구체화하는 사전등록 항목으로 논의할 수 있다. 단, 고정 예측열의 조건부 검사와 자료수신·추출·재학습·후보선택을 포함한 전체 절차 검증의 대상·실패·퇴화·fallback을 먼저 구분해야 한다. 외부 반복 R의 Monte Carlo 정밀도와 내부 bootstrap B를 분리하고, 실패 반복을 버리지 않는다. 시나리오별 실제 포함률·가족 오류율·검정력이 관측되기 전에는 효과 미검증이다. 과거 실패 창을 반복 개봉하거나 유리한 시나리오만 남기지 않는다.

## R3 배당 결의 확인의 근거 범위

**사실:** 현행 삼성 공식 IR 표는 보통주와 우선주 각각4,601원, 3Q 결의 총액30.0조원, 기준일9월30일을 제시한다. R3의 이 수치는 S1에서 직접 대조됐다. 보통주005930의 주당액과 두 종류 주식의 결의 총액을 같은 단위로 섞지 않는다. 총액을 보통주005930 몫으로만 쓰거나 보통·우선 각각30조원으로 쓰면 잘못이다. 대상 주식 수·자기주식·반올림을 확인하지 않아 주당액×유통주식 수로 총액을 재검산한 것은 아니다.

**추론:** 확인한 것은 현재 결의 내용이다. 기준일은 게시일·결의 시각·지급일이 아니다. 분기 결의 총액은 연간 환원 계획 전체의 집행액도 아니다. IR 표와 동일 회사 발표가 같은 결의를 말하면 사건2개·독립 검증2개로 세지 않는다. 현행 확인을 결의일 아침의 입력 적격성이나 오늘의 신규 surprise로 확대할 수 없다.

**제안:** ‘3Q 배당 결의 내용 현재 확인, 지급 완료·과거 가용시각 미확인’으로만 근거 상태를 좁힌다. 지급 사실·시각은 별도 공시/IR 증거가 필요하다. 실제 지급을 나중에 확인해도 앞선 예측 입력을 덮어쓰지 않는다. 시나리오 발동·확률·목표가의 변경 근거로 자동 채택하지 않는다.
