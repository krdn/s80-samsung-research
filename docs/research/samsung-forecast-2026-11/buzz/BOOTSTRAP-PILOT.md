# S80 최초 실응답·산출물 검사

이 검사는5개 프로필을 실제 저장하고 멤버십·모델 설정을 확인한 뒤 수행한다. 현재는 미실행이다.

1. 소유자 측에서 실제5개 pubkey를 TEAM.json에 먼저 등록한다. 소유자Gon이 S80-총괄에게 `[S80-BOOTSTRAP]`을 같은 채널에서 보낸다. 총괄은 기준 문서·운영 계약을 읽고 baseline SHA를 확인한다. 각 역할을 차례로 호출하고 다음 역할 호출 전 앞 역할의 실제 서명 회신·파일을 확인한다.
2. 각 역할은 `runs/bootstrap-<event_id>/bootstrap-<role>.md`에 본인 이름·실행 환경의 실제 모델 확인 범위·기준 문서 SHA·담당·미검증을 적은 작은 Markdown 파일을 저장한다. 이 단계에서 본 연구 문서는 수정하지 않는다. 신원 등록 전의 예외적 bootstrap은 소유자의 직접 요청에만 응답한다.
3. 총괄은 R1/R2/R3의 기존 쟁점 하나씩을 비교해 짧은 candidate.md를 만든다. 외부검토는 그 정확한 SHA의 후보를 읽고 PASS/REVISE/BLOCKED를 반환한다. 전체 주가 성능시험으로 표시하지 않는다.
4. 소유자 측에서 채널/스레드/요청ID·정확한5개 pubkey·모델 설정·실제회신·파일·SHA·검토판정을 확인한다. 모두 맞아야 최초 통신/파일/검토 시범 PASS다. 문서의 정기 갱신 성공이나 미래 예약 실행까지 검증된 것은 아니다.
5. 확인 뒤 TEAM.json에 실제 응답·파일·Workflow ID·검토 증거를 기록하고 활성화본 YAML을 소유자 신원으로 적용한다. 최초 정기 실행 뒤 별도로 예약 발생·갱신 문서·SHA를 검증한다.

파일 존재·online·accepted:true·workflow runs 빈 배열만으로 성공 처리하지 않는다. 실패하면 현재 비활성 예약과 기준 문서를 보존한다.
