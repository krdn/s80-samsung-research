# R2 교차토론 — 데이터 조건과 산업 신호의 검증

2026-11-10 KST. R1의 [조사](01-data-api.md)·[반박](01-data-rebuttal.md), R3의 [산업 연구](03-industry-scenarios.md), [토론 질문](05-discussion-packet.md), [통합안](../samsung-direction-80-research-2026-11.md)을 읽었다. 아래는 **R2의 제안·응답**이며 상대 수용·최종 합의·실측 결과가 아니다. 방향 80%는 미검증 목표이며 달성을 보장하지 않는다.

## 핵심 응답 3개

### 1. R1 보완 ③·질문 ② — 원장과 평가 종결

**정시 예측이 동결된 미평가일만 잠재 적중으로 세자는 제안을 수용한다.** 기존 R2 §1과 통합 §2의 `(H+U)/N`은 다음처럼 좁힌다. `U_on`은 정시 상승·하락 예측이 있고 실제 방향만 미확정인 `pending` 날짜다. 보류·누락·지연은 제외한다. 잠정 범위는 `H/N ~ (H+U_on)/N`이며, 이미 확인한 보합에도 잠재 적중을 부여하지 않는다.

하나의 예정일 원장을 두고 날짜마다 방법별 발행·선택 상태와 평가 상태를 별도 기록한다. 보류와 평가 대기는 동시에 발생할 수 있으므로 상태 건수를 상호 배타적인 하나의 분류처럼 합산하지 않는다. 모든 방법의 `N`은 같은 사전 거래 캘린더로 고정한다. 공급 실패·거래 정지·평가불가를 삭제해 분모를 줄이지 않는다.

**종결안:** 대상일 `T+5 KRX 거래일`까지 가격·조정 근거를 확인한다. 이는 공급 SLA가 아닌 제안 기한이다. 기한 내 해결되면 `evaluated`, 복원 불가이거나 기한까지 해결되지 않으면 사유·확인 기록을 붙여 `closed_unassessable`로 종결한다. 후자는 `N`에 남기고 정답을 부여하지 않는다. 실제 방향 오답으로 확정한 건수와도 구분한다. 창의 마지막 날로부터 같은 기한이 지난 뒤 `pending=0`이면 **서비스 지표인 A_all의 관측 달성·미달**을 마감할 수 있다. 평가불가가 남았다는 이유로 무기한 대기하지 않는다. 이를 순수 시장 방향 능력의 증명으로 표현하지 않는다.

뒤늦은 가격 확보·정정은 새 평가 개정으로 연결한다. 최초 마감 점수와 개정 점수를 함께 공개하고 유리한 개정만 선택하지 않는다. 종결된 건의 재개도 이력에 남긴다. 정정된 점수가 과거 학습·예측에 소급 반영되지는 않는다.

### 2. R1 보완 ①·②·질문 ① — 검증창·후보 비교·재학습

**특징별 가용성 표를 먼저 확정하고, 과거 원문·시점·모델 이용권이 없는 이벤트는 역사 성능 후보에서 제외한다.** M2·M3의 날짜와 입력을 각각 줄여 좋은 기간만 비교하는 안에는 반대한다.

| 실무 조건 | R2 제안 |
| --- | --- |
| 원장·비교 표본 | 같은 예정일 원장에 M2·M3의 예측·이벤트 가용성·보류·라벨 개정을 연결한다. 전체 기간의 방법별 `A_all`과 제공률을 보존한다. 추가 가치 비교의 공통 기간·가용성 규칙은 결과를 보기 전에 고정하고, 제외 날짜·사유·전체 기간과의 차이를 공개한다 |
| M3 이력이 짧을 때 | M2도 그 공통 기간에서 다시 비교한다. M2의 장기 성적과 M3의 짧은 성적을 직접 차감하지 않는다. 데이터가 없는 날과 확인 결과 새 사건이 없는 날을 구분한다. 결측 시 M2로 돌아가는 규칙을 쓰면 그 fallback까지 M3 절차에 사전 포함하고 횟수를 공개한다 |
| 재학습 개정 | 재학습 시각까지 실제 가용한 입력·학습 라벨 개정만 사용하고 목록·해시를 동결한다. 오늘 알려진 정정값은 오늘 이후 학습에 쓸 수 있지만 과거 재학습의 입력으로 소급하지 않는다. 평가 정정은 별도 버전이며 기존 예측을 다시 만들지 않는다 |
| 창 확정 | 특징별 최초·최종 시점, 권리, 시장·세션, 결측 표를 통과한 뒤 개발·보정·외부 평가의 실제 날짜와 재학습 일정을 등록한다. 역사 lockbox 250일과 별도 미래 250일은 현재 설계값이다. 이미 본 역사는 봉인 구간으로 인정하지 않으며, 평가 결과 때문에 종료일을 늘리거나 당기지 않는다 |
| 후보 판정 | M2와 M3는 같은 라벨·날짜·재학습 일정·사전 탐색 예산으로 비교한다. 최소안은 날짜별 적중 차이의 의존 반영 95% 구간 하한 `>0`, Brier 차이 `B_M3-B_M2`의 구간 상한 `≤0`이다. 이는 엄격한 제안이며 실제 이득은 미측정이다. 허용 악화 폭을 도입하려면 최종 개봉 전에 값·이유를 고정한다. 여러 후보를 시험하면 전체 탐색을 통제한다 |

비교가 유리하더라도 M3의 전체 방향 80%가 입증되는 것은 아니다. 보류·제공률이 바뀌면 전체 서비스 성적과 공통 표본의 예측 성적을 함께 해석한다. 역사 이벤트를 복원할 수 없으면 M2 역사 연구와 M3 미래 병행 연구를 분리하고 성적을 합산하지 않는다.

### 3. R3 §3·4·D3 — 산업 가설은 아직 검증 가능한 예측 규칙이 아니다

HBM의 `sample/qualified/shipped`, 환원 단계, 당일 콜 내용 제외, 컨센서스 없는 surprise 금지는 적절하다. 다만 **경로·반증 설명만으로 사건 추출 규칙, 발동 문턱, 유지 기간과 다음날 추가 예측력이 확정되지는 않는다.** 따라서 통합 §5의 산업 설명을 성능 근거로 읽히게 해서는 안 된다.

M3에 넣기 전 사건 정의·중복 제거·가용 시각·만료 또는 경과일 처리·결측 규칙을 고정한다. 분기 호재를 매일 새 사건으로 재발생시키지 않고, 동일 발표문의 재인용·전문가 찬성 수를 독립 근거로 세지 않는다. 현재 LLM이 과거 뉴스에서 만든 라벨은 미래 지식 오염을 통제하지 못하면 미래 관찰용 후보로만 둔다.

검증 질문은 **같은 날짜의 M2에 사건 특징을 추가했을 때 실제로 나아지는가**다. 사건이 있는 날만 사후 선택하지 말고 비사건일·결측일을 포함한 고정 기간에서 위 비교를 수행한다. 사건 수와 날짜 군집을 공개하며 희소·반복 사건의 적은 유효 표본을 큰 일별 표본처럼 해석하지 않는다. 사후 출하 지연 등 반증은 이후 예측·산업 가설의 새 개정에만 반영한다. 이미 동결한 사건 라벨·예측의 사후 재작성이나 오답 삭제에는 쓰지 않는다. 다음날 하락은 방향 오답이고, 장기 산업 경로의 인과 증명 여부는 별도다.

## 동의·남은 결정

- 동의: 통합안의 `A_all`을 **방향 적중 제공률**로 명명하고 조건부 적중률·제공률·보합·평가불가를 함께 표시한다.
- 동의: 로지스틱→얕은 XGBoost→이벤트 추가는 검증 순서다. 실제 우열·80% 기대값이나 전문가 투표의 통계적 독립성을 뜻하지 않는다.

통합 책임자에게 남길 결정은 두 가지다. ① `T+5` 종결·재개 이력 정책을 채택할 것인가? ② 가용성 표 확정 후 실제 검증 날짜와 위 후보 비교 기준을 누가 등록할 것인가? 미정인 동안 합격·자동 승격을 선언하지 않는다. 상대를 직접 호출하거나 답변을 합의로 대신 기록하지 않는다.

## 통합안 수정문

> 전체 예정일 원장은 고정하고, 잠정 적중 상한에는 정시 방향 예측이 동결된 평가 대기일만 포함한다. 평가 대기와 종결 평가불가를 구분하며, 사전 기한 뒤 종결 평가불가는 분모에 남기고 정답을 부여하지 않는다. 마감 점수와 사후 평가 개정을 함께 공개한다.
>
> 특징별 시점·권리·이력 표를 확인한 뒤 검증 날짜와 재학습·정정 규칙을 고정한다. 매 재학습은 그때까지 가용한 개정만 사용한다. 산업 사건의 추가 가치는 같은 날짜의 가격 모델과 비교하고, 장기 산업 설명을 다음날 방향 성능으로 전이하지 않는다. 과거를 복원할 수 없는 사건은 별도 미래 관찰로 검증한다.

수행 범위: 이 파일만 작성했다. 기존 R2 조사·적용 지침을 재사용했으며 새 웹 조사·수치 계산·검사·직접 상대 호출·재위임은 수행하지 않았다. 앱·DB·설정·다른 작업자 파일을 변경하지 않았다. 저장 후 `herdr-core send t4r`로 보고하고 대기한다.
