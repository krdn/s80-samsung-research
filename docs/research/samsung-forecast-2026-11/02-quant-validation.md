# R2 — 삼성전자 방향 예측의 퀀트·통계 검증

독립 1차 연구 / 확인일: 2026-11-10 KST / 입력·현재 revision: `b5610dbcf1c16ffd91aa03725d104d2d4f631a9a`.
기준: [협업 계약](00-brief.md), [제품 계약](../../../HERDR-PROJECT.md), [실행 부록](../../../HERDR-OPERATIONS.md).

## 결론

**삼성전자 다음 거래일 상승·하락 방향 적중률 80%는 연구 목표다. 이번 조사에서는 달성 근거나 달성 보장을 확보하지 못했다.** 다른 시장·기간·목표의 논문 성적을 삼성전자에 전이할 수 없다. 반대로 이번 조사로 80%가 불가능하거나 특정 논문 수치가 성능 상한이라고 결론 내릴 수도 없다.

권고는 `시점 일치 자료 → 단순 기준선 → 로지스틱·제한된 트리 부스팅 비교 → 미사용 최종 구간 → 미래 전향 관찰`이다. 모델 규모보다 누출·반복 탐색·평가 분모를 먼저 통제한다. 현재 삼성전자 데이터를 학습하거나 백테스트하지 않았다. 아래 수치 예시는 **가상의 적중 횟수에 대한 직접 계산**이며 실제 성적이 아니다.

용어: PIT는 당시 이용 가능했던 자료, nested walk-forward는 시간순 내부 선택·외부 평가, lockbox는 선택에 쓰지 않는 최종 구간이다. purge는 경계를 침범한 학습 라벨 제거, embargo는 경계 주변 자료의 사용 유예다. 보정은 예측 확률과 실현 빈도의 일치, conformal은 예측 집합·구간의 포함률을 다루는 방법이다. shadow forward는 실제 시각에 동결하되 운영 방법을 바꾸지 않는 병행 관찰이다.

## 1. 80%의 분자와 분모

연구 대상은 삼성전자 보통주 `005930`, KRX 정규시장 종가다. 거래일 `t`의 비교 가능한 전일 종가를 `C_prev`, 당일 종가를 `C_t`라 하면 `r_t=C_t/C_prev-1`이다. 예측은 전 거래일 종가 이후부터 대상 거래일 07:40 KST까지 이용 가능한 정보로 만들고, 08:00에 실제 공개·동결한다. 미국 거래일을 한국 날짜에 기계적으로 맞추지 않는다.

`r_t>0`은 상승, `r_t<0`은 하락, 정확히 0이면 보합이다. `±0.5%`의 기존 제품 3분류는 별도 지표로 유지한다. 보합을 상승에 합치거나 작은 수익률을 사후 제거하지 않는다. 가격 비교는 사전에 고정한 기업행사·조정 정책을 따른다. 기준 가격을 복원하지 못한 날은 평가 불가로 공개한다. 최신 수정주가를 과거 입력의 당시 버전으로 간주하지 않는다.

**연구 제안:** 목표 판정에는 전체 예정일 분모를 사용한다. 이는 보류를 포함한 서비스의 방향 적중 제공률이며, 답한 날만 계산하는 조건부 정확도와 구분한다.

| 기호·지표 | 정의·처리 |
| --- | --- |
| `N` | 사전 확정 거래 캘린더의 전체 대상 거래일. 휴장일은 처음부터 제외하고 거래 정지·공급 실패는 따로 표시 |
| `H` | 정시 동결한 상승·하락 예측이 최종 비교 가능한 실제 방향과 일치한 횟수 |
| `A_all=H/N` | 80% 목표의 보수적 주 지표 제안. 보합·보류·누락·지연은 정답으로 세지 않음 |
| `Q`, `A_select=H/Q` | 정시 방향 예측과 평가 가능한 실제 비보합 방향이 모두 있는 날의 수와 조건부 적중률 |
| 선택률·보류율 | 정시 방향을 제시한 날/N, 명시적으로 보류한 날/N. 누락·지연은 별도 비율로 표시 |
| `A_nonflat` | 평가 가능한 비보합 전체 날짜를 분모로 하는 보조 지표. 그 날짜의 보류·누락·지연도 정답 제외 |
| 확률·범위 | 이진 Brier `mean((p_up-y)^2)`, log loss, 신뢰도 도표, 구간 실제 포함률·폭. 각 계산 표본과 제외 수 표시 |

미평가일은 오답이 확정된 날과 구분한다. 미평가일을 `N`에서 지우지 않고 `H/N`은 잠정 보수값으로 표시한다. 미평가 `U`일이 전부 적중한다고 가정한 상한 `(H+U)/N`도 함께 보인다. 최종 합격 판정에는 미해결 평가가 없어야 한다. 보합·보류·결측 사유를 전체 일정 원장에 남겨 성적이 좋은 날만 고를 수 없게 한다.

예: 예정 250일 중 50일에만 방향을 제시하고 40일 맞히면 `A_select=80%`, 선택률 20%, `A_all=16%`다. 전체 방향 목표 80%의 달성으로 표현할 수 없다. 확률 0.8 출력, 80% 예측구간 포함률, 투자 수익률 80%도 방향 적중률과 다른 수치다.

**추천 순서(연구 제안):** 과거 자료로만 정한 상승 빈도·다수 방향, 항상 상승, 직전 비보합 방향 유지를 기준선으로 둔다. 그 다음 소수의 사전 정의 특징을 쓰는 정규화 로지스틱과 XGBoost를 비교한다. LightGBM은 대안이며 자동 우승자가 아니다. 깊이·최소 잎 표본·학습률·반복 수의 탐색 범위를 제한하고 모든 시도를 기록한다. LSTM·TFT·대형 사전학습 시계열 모델은 초기 운영 채택을 보류한다. 동일 라벨·PIT 입력·평가 구간에서 추가 이득을 확인하면 판단을 바꾼다.

**확률·보류 판단:** 별도 과거 보정 구간에서 로지스틱 방식이나 temperature scaling을 비교한다. 작은 보정 표본의 유연한 isotonic 회귀는 우선 보류한다. 보정 방법도 탐색 횟수에 포함한다. 기준 확률은 학습 구간에서만 구하고, Brier는 같은 날짜끼리 비교한다. 결측 확률을 임의로 0.5로 채우지 않는다. 공통 완전 표본에서 계산한 점수에는 제외 수를 함께 표시한다.

Conformal의 명목 80%는 집합·구간에 실제값이 포함될 확률이다. 방향 선택의 정확도가 아니다. 예를 들어 단일 원소 집합만 선택하더라도, 주변적 오포함률 `alpha`만 알면 선택 조건부 오답률의 상한은 일반적으로 `alpha/P(선택)`까지 커질 수 있다. 따라서 구간이 0을 벗어나는 날만 제시하는 방식도 선택률·조건부 성적을 별도 전향 검증한다. LLM 전문가 수·같은 모델의 seed 수를 독립 표본 수로 세지 않는다.

## 3. 누출과 탐색을 막는 검증 설계

아래 기간·횟수는 **실험안**이며 현재 구현이나 통계적 충분성의 증거가 아니다. 기존 제품의 120일 자료·20일 최종 구간·20일 병행은 검증 착수 기준으로 남긴다. 80%를 입증하는 충분 조건으로 격상하지 않는다.

1. **PIT 입력을 먼저 고정한다.** 발행·관측·최초 수집·수정 시각과 당시 버전을 보존한다. `available_at=max(발행 가능 시각, 실제 수집 시각)`이 07:40 이하여야 한다. 과거 수집 시각을 복원할 수 없는 자료는 역사 실험의 한계로 표시하고 실시간 성적과 합치지 않는다. 공시 정정·거시 vintage·당시 뉴스·조정주가를 현재 완성본으로 대체하지 않는다. 정규화·결측 대체·특징 선택도 학습 구간에서만 적합한다.
2. **내부 선택과 외부 평가를 시간순으로 분리한다.** 개발 예시: 외부 학습 최소 756거래일, 다음 63일 평가를 네 번 진행한다. 각 외부 학습 안에서 과거 최소 504일 학습과 뒤 63일 검증을 순차 반복한다. 후보·특징·조기 종료·보정·보류 문턱은 내부 구간에서만 선택한다. 보정 구간은 해당 기본 모델 적합에서 제외한다. 외부 구간은 실행 절차를 평가하고, 이를 보고 설계를 바꾼 경우 개발 자료로 취급한다.
3. **경계는 라벨의 실제 시간으로 검사한다.** 학습에는 다음 예측 마감까지 결과가 확정·수집된 라벨만 넣는다. 검증 결과 기간을 침범하는 학습 라벨은 purge한다. 5·20일 전망이나 이벤트 만기에는 실제 라벨 종료까지 확장한다. 과거 rolling 입력을 공유한다는 이유만으로 무조건 수백 일을 제거하지 않는다. 반대로 같은 날 종목을 다른 fold에 나누어 미래 결과를 노출하지 않는다. 엄격한 과거→미래 구조는 시험 뒤의 미래 학습을 사용하지 않으므로, 추가 embargo 길이는 라벨 중첩·수집 지연에 근거해 사전 고정한다. 임의의 1% embargo를 만능 규칙으로 삼지 않는다.
4. **최종 lockbox를 한 번만 연다.** 아직 분석·선택에 사용하지 않은 연속 역사 250거래일을 별도 보관한다. 후보 하나와 재학습 일정·보정·보류 규칙·지표·최소 개선폭을 개봉 전에 동결한다. 구간 내 재적합을 허용한다면 과거에 확정된 라벨만 쓰는 일정까지 고정한다. 개봉 후 실패를 보고 문턱을 바꾸면 새 방법이며 새 최종 구간이 필요하다. 이미 본 과거이거나 LLM 사전학습 오염 가능성이 있으면 진정한 미사용 평가로 간주하지 않는다.
5. **탐색을 가족 단위로 기록한다.** 모델·특징·보정·프롬프트·문턱·기간 선택을 모두 실험 원장에 남긴다. 개발 비교에는 전체 후보의 날짜별 손실 차이를 사용하는 White Reality Check 또는 사전 지정한 가족단위 보정을 적용한다. PBO/CSCV는 후보 선택 불안정의 보조 자료다. 미래 자료를 쓰는 분할 결과를 실제 08시 워크포워드 성적으로 표시하지 않는다. Sharpe용 보정을 방향 적중률 검정에 그대로 쓰지 않는다.
6. **미래 shadow forward 250거래일을 별도로 관찰한다.** 같은 07:40 마감·08:00 동결로 현행·후보·기준선을 함께 저장한다. 미공개 내부 방향과 공개 보류 여부도 사전에 고정한다. 역사·전향 점수를 합쳐 하나의 실운영 실적처럼 제시하지 않는다. 첫 20일은 수집·동결·평가의 기능 점검이지 성능 입증이 아니다. 최종 기간·검정은 시작 전에 정한다. 매일 관찰하되 80%가 되는 날 임의로 종료하지 않는다. 중간 성능 종료가 필요하면 사전 설계한 순차 검정이 필요하다.

## 4. 상관과 통계적 불확실성

**기본 추론 단위는 날짜다.** 삼성전자와 하이닉스를 함께 분석해도 같은 날 두 결과를 독립 시행 두 개로 세지 않는다. 시장·산업 충격을 함께 받는 날짜 벡터를 통째로 재표집한다. 삼성전자 단독 결과를 주 결과로 유지하고 종목 합산 성적을 대신 제시하지 않는다.

실제 성적의 구간은 정답·선택·보류·기준선 손실을 포함하는 전체 날짜 원장을 날짜 블록으로 재표집해 구한다. 선택한 날짜만 압축하면 시간 간격과 상관 구조가 깨진다. Stationary bootstrap의 평균 블록 길이 10일, 민감도 5·20일, 재표집 10,000회를 개발 단계에서 고정하는 안을 제안한다. 각 재표집에서 적중률과 선택률의 분모를 다시 계산한다. 선택 표본이 없는 재표집은 임의의 100%로 채우지 않는다.

정답 지표와 후보–기준선 손실 차이의 자기상관을 살핀다. 상관이 길면 블록 길이를 개발 자료에서 재선정하고 새 평가 전에 동결한다. 최종 구간에서 가장 유리한 블록 길이만 골라 보고하지 않는다. 구조 변화가 심하거나 블록 수가 부족하면 부트스트랩도 신뢰하기 어렵다. 연도·변동성·상승/하락 국면별 표본과 성적을 함께 제시하고 **근거 부족**을 허용한다. 미래 국면에 대한 보장은 하지 않는다.

기준선 대비 방향 차이는 같은 날짜의 `d_t=hit_candidate-hit_baseline`으로 계산한다. 최상 기준선은 개발에서 선택하고 고정한다. 모든 예정일 기준의 후보 차이와 같은 선택 날짜에서의 조건부 차이를 각각 보고한다. Brier 차이도 날짜별로 짝지어 재표집한다. 무조건 상승 기준선보다 나은지 검증하지 않고 50% 동전만 기각해서는 충분하지 않다.

### 가상 표본에서 80%를 관측한 경우

아래는 독립·동일한 성공확률의 Bernoulli 시행을 **가정한 설명용 계산**이다. 실제 금융 자료에 대한 구간은 아니다. 양측 95% Wilson 구간을 사용했다.

| 평가 수 `n` | 가상 적중 `k` | 관측값 | Wilson 95% 구간 |
| --- | --- | --- | --- |
| 20 | 16 | 80.0% | 58.40~91.93% |
| 60 | 48 | 80.0% | 68.22~88.17% |
| 120 | 96 | 80.0% | 71.96~86.18% |
| 250 | 200 | 80.0% | 74.60~84.49% |
| 500 | 400 | 80.0% | 76.27~83.27% |
| 1,000 | 800 | 80.0% | 77.41~82.36% |
| 250 | 213 | 85.2% | 80.27~89.07% |

정확히 80%를 관측하면 표본이 늘어도 구간 하한은 80% 아래다. i.i.d. 가정에서 양측 95% Wilson 하한이 80% 이상인 250일 최소 예시는 213회 적중이다. 이는 실제 시계열의 합격 횟수가 아니다. 의존·다중 탐색을 반영한 구간은 별도로 필요하다. `250일 확보` 자체는 검정력 보장이 아니다. 예상 실제 성능, 허용 오차, 자기상관에 따라 필요 기간을 미리 시뮬레이션해야 한다.

재현 계산: Python 3 표준 라이브러리로 아래 코드를 직접 실행했다. 구간 계산과 250일 최소 횟수의 결과를 대조했다.

```python
from math import sqrt
from statistics import NormalDist

def wilson(k, n):
    z = NormalDist().inv_cdf(0.975)
    p = k / n
    den = 1 + z*z/n
    center = (p + z*z/(2*n)) / den
    half = z * sqrt(p*(1-p)/n + z*z/(4*n*n)) / den
    return center-half, center+half

for n, k in [(20,16), (60,48), (120,96), (250,200),
             (500,400), (1000,800), (250,213)]:
    print(n, k, tuple(round(100*x, 2) for x in wilson(k, n)))
print(next(k for k in range(251) if wilson(k, 250)[0] >= 0.8))
```

## 5. 합격·실패·근거 부족의 판정

아래는 **사전 고정할 판정안**이다. 이번에는 실제 데이터로 수행하지 않았다. 역사 lockbox와 미래 shadow를 각각 판정하며, 결론은 관찰 기간과 검증 가정 안으로 제한한다.

| 판정 | 사전에 충족할 조건·보고 방법 |
| --- | --- |
| 검증 무효 | 미래 정보, 최종 구간 재사용, 라벨 변경, 미기록 탐색 발견. 높은 적중률도 성능 근거로 채택하지 않음 |
| 표본에서 80% 관측 | 고정 기간의 `A_all>=0.80`. 이것만으로 기저 적중 확률 80% 이상을 확인한 것은 아님 |
| 80% 이상을 지지하는 제한적 근거 | 두 기간 각각 `A_all`의 의존을 반영한 95% 구간 하한이 0.80 이상. 주 분석·민감도 분석이 모순되지 않고 미평가 없음. 아래 비교·품질 조건도 충족 |
| 기준선보다 개선 | 같은 날짜의 주 방향 지표에서 후보－고정 기준선 차이의 구간 하한이 사전 최소 개선폭을 초과. 최소 폭·다중 비교 처리가 미정이면 합격 판정 보류 |
| 확률·제공 품질 | Brier 비열등성 폭, 최소 선택률, 최대 지연율, 결측 허용량을 사전 고정. 조건부 80%로 전체 목표를 대체하지 않음. 값이 미정이면 자동 승격 보류 |
| 근거 부족 | 구간이 0.80을 포함하거나 표본·유효 블록 부족, 미평가가 남음. 합격으로 부르지 않고 추가 관찰 필요성을 판단 |
| 고정 기간 목표 미달 | `A_all<0.80`. 구간 상한도 0.80 미만이면 그 기간·가정 안에서 80% 미만을 지지. 미래의 불가능성·보편적 상한은 주장하지 않음 |

## 6. 핵심 반론 3개와 미해결 질문

1. **“고확률인 날만 골라 80%면 충분하다.”** 선택적 예측은 유용할 수 있지만 목표가 바뀐다. 전체 예정일 적중 제공률·선택률·조건부 적중률을 함께 고정하지 않으면 보류로 성적을 만들 수 있다.
2. **“금융 딥러닝 논문이 우수하므로 삼성전자도 된다.”** 원논문의 종목군·라벨·정보 시각·수익률 지표가 다르다. 특히 S4의 단면 중앙값 분류와 S5의 변동성 분위수는 절대 방향 적중률이 아니다. 동일 조건의 삼성전자 실험이 필요하다.
3. **“250일·보정·conformal·전문가 합의가 있으면 80%를 보증한다.”** 표본 수는 검정력, 보정은 확률 신뢰도, conformal은 포함률의 문제다. 서로 다른 개념을 합쳐 방향 보장을 만들 수 없다. 독립적인 미래 관찰과 실패 판정이 필요하다.

미해결: 과거 07:40 PIT 자료를 어느 기간까지 복원할 수 있는가? 비교 가능한 가격·보합·거래 정지 정책은 무엇인가? 기존에 본 과거와 오염되지 않은 lockbox를 어떻게 식별할 것인가? 최소 방향 개선폭·Brier 비열등성 폭·제공률 기준과 미래 250일 관찰 운영자는 누구인가? 이 질문은 통합 책임자의 후속 결정 사항이며 이번에 설정·코드를 변경하지 않았다.
